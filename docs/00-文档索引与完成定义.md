# 文档索引与完成定义（Definition of Done）

> **文档性质**：项目治理与交付门禁，所有规划、开发、审查和文档任务开始及完成前必读
> **版本**：v1.0（试点）
> **创建日期**：2026-08-07
> **状态**：在本项目试运行，评估后再抽取通用模板推广到其他项目

---

## 1. 核心原则

1. **开发顺序可以灵活，完成标准不能省略。**允许文档先行，也允许代码先行。
2. 代码先行时，任务计划或进度记录必须标记 `DOC_SYNC_PENDING`；相关文档同步前不得宣布任务完成。
3. 项目仓库中的文档和代码是权威资产。Codex/Claude Memory 只能保存偏好和入口路径，不能代替本文件。
4. 不为“看起来完整”而机械修改文档。若本次无需更新文档，交付摘要必须写明理由。
5. 历史方案不直接抹除：保留历史正文，在顶部标明状态并指向现行依据。

## 4. 两种允许的工作方式

### 4.1 文档先行

1. 更新现行权威文档并标出待实施内容。
2. 根据文档实施代码。
3. 验证实现与文档一致，移除待实施标记。

### 4.2 代码先行

1. 在任务计划或进度中标记 `DOC_SYNC_PENDING`，列出可能受影响的文档。
2. 完成代码和验证。
3. 根据最终实现更新文档；若决策发生变化，同时记录原因。
4. 清除 `DOC_SYNC_PENDING` 后才能交付。

## 5. Definition of Done

以下条目按任务影响范围执行；不适用的条目应在交付摘要中说明，而不是静默跳过。

### 5.1 开始前

- [ ] 已读取根目录 `AGENTS.md` 或 `CLAUDE.md`、本文件及本次涉及的现行权威文档
- [ ] 已重新核验任务计划前置条件、适用锁、分支、HEAD、upstream 与工作树状态
- [ ] 已区分用户已有改动与本次任务范围，确认单写者边界
- [ ] 已判断采用文档先行还是代码先行；代码先行已标记 `DOC_SYNC_PENDING`

### 5.2 代码与文档一致性

- [ ] 已列出受影响文档并完成同步，或明确记录无需更新的理由
- [ ] 被取代的旧方案已标明历史状态并指向现行依据
- [ ] 删除、移动、重命名后已用 `rg` 检查代码和文档残留引用
- [ ] README、注释、类型和实际实现不存在已知冲突

### 5.3 质量门禁

- [ ] 运行与影响范围相称的 `typecheck`、`lint`、`build`、测试或针对性验证
- [ ] UI/交互变更已检查相关桌面与移动场景、键盘操作及必要的可访问性状态
- [ ] 性能相关变更已记录前后指标，且没有突破现行预算
- [ ] 未通过删除测试、降低校验或隐藏错误来绕过根因

纯文档任务若未修改代码、依赖或配置，可以不重复执行代码构建，但必须运行链接/引用检查和 `git diff --check`，并在交付摘要说明跳过原因。

### 5.4 交付前

- [ ] `DOC_SYNC_PENDING` 已清除
- [ ] 工作树中没有临时脚本、日志、构建产物或非预期文件
- [ ] 已记录分支、HEAD、upstream ahead/behind 和规范化 Git 状态
- [ ] 交付摘要包含：实现、文档、验证结果、未覆盖项、风险和建议的手动 Git 命令
- [ ] 未经用户当前任务明确授权，没有 commit、push、PR、发布或部署

只有以上适用项完成后，任务才能标记为 `READY_FOR_HANDOFF`。前置条件漂移时报告 `STATE_DRIFT`；文档尚未同步时保持 `DOC_SYNC_PENDING`。

## 6. 试点与推广

本项目是 DoD 首个试点。先用于至少 3 次有实质代码或架构影响的迭代，再决定是否推广。

试点评估四项：

1. 是否提前发现了代码/文档漂移；
2. 是否减少了返工和重复 AI 审查；
3. 哪些条目经常不适用或造成无效负担；
4. 是否有适合自动化的稳定检查，例如构建体积、死引用和关键交互回归。

每次试点任务交付后，在下表增加一行；不追求长复盘，只记录能支撑取舍的证据。本规则生效前已完成的任务不倒算试点次数。

| # | 日期 | 任务/交付物 | 工作方式 | DoD 发现的问题 | 无效负担 | 自动化候选 | 结论 |
|---|---|---|---|---|---|---|---|
| 1 | 2026-08-07 | 工具页极简化、空白初始态与结构化数据纠偏 | 代码先行（已清除 `DOC_SYNC_PENDING`） | 发现 01/02/03/03-1/04 仍要求工具页 SEO 内容或示例预填；实现删除文件后需区分现行与历史引用 | 全库引用检查会命中已标记为历史的 05/07，不能机械要求归零 | 6 路由文案/Schema smoke、空编辑器与 sessionStorage/移动端回归、现行文档冲突词检查 | 保留，继续第 2 次试点 |

满足以下条件后才进入推广：完成至少 3 次试点、没有未解决的高频无效负担、交付口径已稳定，并由项目所有者确认。

推广时只复用通用骨架：工作方式、DoD、交付口径和平台入口。每个项目必须单独维护自己的文档权威关系、验证命令和风险清单，不能直接复制本项目的技术细节。
