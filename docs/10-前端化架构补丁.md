## 1. 背景与决策

### 1.1 触发因素

01–07 文档定义的是一套**前端 (Vercel) + 后端 (Render/Fly Puppeteer) + Supabase** 的三层架构，原始成本估算 $8.67–26.67/月。在 2026-05-13 接近上线时，作者基于以下事实回看了这套架构：

| 输入 | 内容 |
|---|---|
| 历史数据点 1 | WeeklyPlanner 上线至今付费用户 0 |
| 历史数据点 2 | MindTypo 上线至今付费用户 0 |
| 当前认知 | 本项目（MD → PDF/Word/HTML）所属类目（在线小工具）海外付费率历史上同样偏低 |
| 当前阶段 | **流量是否存在尚未验证**，不是付费转化率问题 |

结论：在流量验证之前持续每月 $7–25 的 backend 固定成本是**用现金购买不必要的复杂度**。

### 1.2 决策

**全部转换路径搬到浏览器**：PDF、Word、HTML 三种格式均在用户本地浏览器完成生成，不经过 backend。$0/月运行成本（仅域名年费 ~$20）。等真实流量与付费意愿数据出来之后，再决定是否重启 backend。

### 1.3 与 01-04 文档的关系

01（项目主线）、02（SEO）、03/03-1（产品结构 / 交互）、04（UI 规范）**完全不受影响**。这些是产品定位与用户层文档，技术路径变更不动它们。

## 3. 当前实际架构

### 3.1 整体数据流

```

│                    用户浏览器                              │
│                                                          │
│  ┌──────────────┐    ┌──────────────────────────────┐   │
│  │ CodeMirror 6 │───▶│ unified (remark + rehype +   │   │
│  │  编辑器       │    │  rehype-sanitize)            │   │
│  └──────────────┘    └──────────┬───────────────────┘   │
│                                 │                        │
│                  ┌──────────────┼────────────────┐      │
│                  ▼              ▼                ▼      │
│           ┌──────────┐   ┌──────────┐    ┌──────────┐   │
│           │ PDF 路径  │   │ Word 路径 │    │ HTML 路径 │   │

│           │ .print() │   │ Packer    │    │  API      │   │
│           │ + iframe │   │ .toBlob() │    │           │   │
│           └─────┬────┘   └─────┬─────┘    └─────┬─────┘   │
│                 │              │                │        │
│                 ▼              ▼                ▼        │
│              用户保存          下载 .docx       已复制     │
│              (Save as PDF)                              │
└─────────────────────────────────┬────────────────────────┘
                                  │
                                  │ (fire-and-forget)
                                  ▼
                       ┌──────────────────┐
                       │ Supabase         │
                       │ - Auth (登录)     │
                       │ - conversion_    │
                       │   history (日志)  │
                       └──────────────────┘
```

**应用自身数据调用仅有 Supabase**（Auth登录、conversion_history写入）；Markdown中的外部图片仍由浏览器按URL加载。没有自营backend转换endpoint。

### 3.2 PDF 路径

实现位置：`frontend/lib/converter/pdf-print.ts`

机制：
1. 把 Markdown 经 unified + rehype-sanitize 渲染成 HTML
2. 创建隐藏 `<iframe>` 注入完整 HTML 文档（含 `PRINT_STYLES` 内联样式）
3. 调用 `iframe.contentWindow.print()` 触发浏览器原生打印对话框
4. 用户在打印对话框选择"另存为 PDF"

**优点**：零成本、零依赖、零延迟，浏览器 Chromium 引擎自带的 PDF 渲染质量足以满足海外工具站基础需求。

**已知限制**：
- 无法在代码中检测用户是 Save 还是 Cancel（受浏览器 API 约束）
- 无服务端 PDF 模板能力（页码、页眉、水印等高级特性不可用）
- 代码块当前仅黑灰单色高亮，未实现 hljs 彩色配色（可后续在 `PRINT_STYLES` 中内联 `github-markdown-css` 主题）

### 3.3 Word 路径

实现位置：`frontend/lib/converter/word-export.ts`

机制：
1. 把 Markdown 经 `remark-parse + remark-gfm` 解析为 mdast
2. 自定义遍历器 `convertNode` 把 mdast 节点映射成 `docx` 包的 `Paragraph` / `Table` / `TableRow` 对象
3. `Packer.toBlob(doc)` 输出 `.docx` Blob

样式取自 `D:\GoodApp\ABeiTools_V2` 的 md2word 模块（已为中文场景多轮调试）：
- 基础字体：**微软雅黑**，确保 Word/WPS 上中文不回退到 Calibri
- Heading1-6 字号阶梯：32 / 28 / 26 / 24 / 24 / 24 半磅
- 有序列表渲染为明文 `"1. "` 前缀（不用 docx 的 numbering.config，避免独立列表共享 numbering ref 导致序号跨列表续编）
- 行内样式累积器（`collectInlineRuns → toTextRun`）：保留嵌套 bold / italic / strike / inlineCode / link

### 3.4 HTML 路径

实现位置：`frontend/lib/converter/html-export.ts`（剪贴板）+ `frontend/lib/markdown/render.ts`（渲染）

机制：
1. 把 Markdown 经 unified（含 **rehype-sanitize 防 XSS**）渲染为 HTML 字符串
2. 通过 `navigator.clipboard.writeText()` 直接写入剪贴板

用户用例：粘贴到富文本编辑器（Notion、飞书、邮件正文等）。

## 4. 数据流（Supabase）

### 4.1 Auth

不变：Supabase Auth（邮箱密码 + Google OAuth）。登录后 cookie 由 `@supabase/ssr` 管理。仅用于 Dashboard 历史记录 SELECT 时的 `auth.uid()` 限定。

### 4.2 conversion_history

| 项 | 当前行为 |
|---|---|
| 是否登录用户必写 | 否，匿名用户跳过 |
| 写入方 | **浏览器 Supabase Client**（service_role 已不需要） |
| 写入时机 | 转换成功后，`fire-and-forget` IIFE 包裹，不 await，**不影响下载** |
| RLS 策略 | `WITH CHECK (auth.uid() = user_id)` —— 三种 format 一视同仁 |
| 失败容忍 | Supabase 短暂不可用不影响转换功能本身 |
| PDF 特例 | 由于浏览器 print API 无法区分 Save vs Cancel，**PDF 不写 history**（避免误报） |

### 4.3 daily_usage

表保留（迁移 `20260323100348` 创建），但写入路径已断（无 backend、无配额）。不删除是为了未来重启 backend 时减少迁移成本。

### 4.4 record_conversion RPC

09 号补丁中的 RPC 函数（迁移 `20260513065047`）保留但未调用。同 daily_usage：保留作冷备。

3. 重新启用 09 号补丁的 record_conversion RPC + JWT 校验
4. 把 08 号补丁的 Puppeteer sandbox 节恢复为强制要求

## 9. 2026-10-04 可靠性、Worker与静态化增强（现行）

### 9.1 转换与输入

- useConversion统一下载/打印/复制的同步锁、操作编号、定时器清理和错误翻译；重试保存失败源码快照，源码/格式变化后失效，卸载后不发起迟到下载。Supabase历史仍最佳努力，读取/写入error不会阻塞本地转换。
- readMarkdownFile统一扩展名和读取异常；严格UTF-8及BOM UTF-16先行，失败后按需加载jschardet，使用分块二进制字符串检测和原生TextDecoder解码。前端不再依赖Buffer或iconv-lite。
- 草稿共享内存即时更新，sessionStorage防抖300ms，导航/页面隐藏/pagehide立即flush；存储失败可保持SPA内存草稿，但不能可靠跨整页刷新。跨语言/root导航在保存失败时拦截，刷新显示浏览器离开提醒。

### 9.2 渲染和统计

- render-core并行加载remark/rehype，复用processor；初始化失败清空失败Promise。sanitize白名单不变，正文提取在sanitize后/highlight前，collectText是每个VFile的选项，不使用可变全局选项。
- renderMarkdown返回html、可选plainText及stats；renderMarkdownToSafeHtml保持字符串接口。明确语言继续高亮，未标注代码不自动猜测，未知语言保留纯文本。
- 客户端解析/高亮/正文分词移到共享Worker，按请求ID配对结果，预览取消过期UI结果。Worker不可用/启动失败时回退同一个安全core；单次解析错误保留错误状态且允许后续重试。
- decode-named-character-reference的browser入口依赖document，Worker不能使用。next.config对Webpack和Turbopack均固定到该包的纯查表默认入口；Turbopack别名相对于frontend应用目录，root覆盖pnpm workspace。生产与开发浏览器均已验证实体渲染。
- 预览上限为200KiB UTF-8，逐码点截断；仅片段渲染及片段统计，导出始终处理完整源码，没有500KiB硬上限。删除前端未使用MAX_REQUEST_BODY，冷备后端/shared常量保留。
- 源码字符包含空白/格式，正文字符排除空白、HTML属性及链接地址，包含标题/代码/表格文本；码点计数，固定en分词，不等同Word字数。统计仅工具页开启，清空立即归零、失败保留上次值并提示。

### 9.3 Word输出

- 列表/引用递归上下文累加缩进，列表项仅首段有标记；混合/嵌套编号独立，任务保留☐/☑，代码使用显式w:br。
- 表格及单元格使用匹配DXA宽度，扣除引用/列表缩进后保持在A4文本区内；表头底纹明确clear，官方OOXML校验通过。
- 图片替代文字及非br原始HTML处理边界不变。实际导出样例已由本机WPS的Word兼容COM接口只读打开（24段落、1表，嵌套及任务文字存在），并经独立LibreOffice转PDF逐页视觉核对。未修改或关闭用户原有WPS文档。

### 9.4 公共路由与缓存

- 语言段成为根布局，直接生成html lang；默认路由组保留/到/en的308。共享DocumentShell负责本地字体、样式基类和metadata。
- 当前Next 15.5.14启用实验globalNotFound以支持多根/动态根布局全局404；未知语言/路由/指南均返回404。指南slug dynamicParams=false。
- 移除根headers()及x-pathname传递；middleware只匹配en/zh Dashboard/Auth和/auth回调。公共Header认证状态在浏览器维护，公共HTML不包含用户数据；Dashboard force-dynamic并继续getUser及RLS校验。
- 本地生产HTTP验证：公共工具页s-maxage=31536000且无Set-Cookie；Dashboard未登录307且private/no-store；根308、404、robots、sitemap正常。缓存实测是验收依据，不能只根据Next构建列表的SSG符号判断。
- 原URL、canonical、hreflang、OAuth回调和数据库schema不变；发布仍按DEPLOY单独执行。

### 9.5 验证与性能记录

- Node22.23.3、pnpm10.28.1：30项回归测试、typecheck、lint通过；生产构建与Turbopack开发Worker实体渲染已验证。
- 工具页First Load JS：改动前295kB，改动后176kB（约40%减少，Next构建报告口径）。
- 相同71,208字节未标注代码块样例，Node24本机6次core基准：原自动猜测热运行591/597/675/749/769ms，中位675ms；关闭猜测并收集统计后29/29/25/28/35ms，中位29ms。此为解析基准，不代表真实网络首屏或手机耗时。
- 含中英文/链接/加粗的68,410字节样例仍有77–98ms热运行，超过50ms解析长任务预算，因此启用Worker保持输入线程可用；统计和DOM插入不作为相同耗时指标混报。
- 已检查中英文断点、上传.MD、清空/撤销、格式/语言切换、完整长文导出单测、实体/安全过滤和Worker故障回退。真实Google OAuth/已登录历史写入、iOS/Safari软键盘与打印保存未联调；本地使用占位Supabase配置，无生产服务写入。


**下载自动化边界**：浏览器Word按钮已显示Downloaded反馈，导出样例实际生成并由WPS兼容接口打开；HTML下载事件未被浏览器自动化捕获。Windows系统窗口控制入口返回native pipe不可用，未自动确认系统另存为环节及最终下载文件落盘。此项列为发布前手动复核，不把按钮反馈当作落盘证明。

**框架日志限制**：Next15在部分未知动态参数请求上会打印内部NoFallbackError日志；本地对应HTTP响应仍为404且未返回内部堆栈。globalNotFound为实验功能，框架升级时应复测并关注错误监控噪声，不通过过滤日志隐藏此现象。
