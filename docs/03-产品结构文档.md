## 1. 产品定位简述

**一句话定位**：面向海外用户的免费在线 Markdown 格式转换工具，支持 MD→PDF / Word / HTML 三种格式输出。

**核心价值主张**：打开即用，粘贴即转——让"被 AI 塞了一堆 Markdown 的普通人"30 秒内完成格式转换。

**与竞品的关键差异**：
- vs markdowntopdf.com：多格式支持（PDF+Word+HTML）、现代 UI、实时预览
- vs markdownguide.org（指南页层面）：交互式编辑器体验、语法学习→转换工具的无缝衔接

## 4. 各模块职责说明

### 4.1 编辑器模块 (Editor)

| 维度 | 说明 |
|------|------|
| **输入** | 用户键入的 Markdown 文本；拖拽/上传的 .md 文件内容 |
| **输出** | Markdown 原文字符串（传给转换模块）；实时渲染的 HTML 预览 |
| **核心组件** | `MarkdownEditor` — CodeMirror 6 实例，支持语法高亮、行号 |
| | `MarkdownPreview` — 实时渲染预览面板（unified: remark + rehype） |
| | `FileDropzone` — 拖拽区域 + 文件选择按钮 |
| **边界** | 编辑器模块不负责转换逻辑，只负责内容的输入和预览展示 |
| **精简版** | `MiniEditor` — 用于指南页，仅保留编辑+预览，去掉文件上传和转换按钮 |
| **移动端** | 编辑器和预览面板上下排列（而非左右），可通过 Tab 切换编辑/预览视图 |

### 4.2 转换模块 (Converter)

| 维度 | 说明 |
|------|------|
| **输入** | Markdown 原文字符串 + 目标格式（pdf / docx / html） |
| **输出** | 生成的文件（PDF blob / Word blob / HTML 字符串）→ 触发浏览器下载 |
| **PDF** | 前端发送 Markdown → Render 后端 Puppeteer 渲染 → 返回 PDF 流 |
| **Word** | 前端发送 Markdown → Render 后端 docx 包生成 → 返回 .docx 流 |
| **HTML** | 纯前端处理：Markdown → HTML 字符串 → 下载为 .html 文件 或 复制 HTML 源码到剪贴板 |
| **边界** | 不涉及用量判断（由 RateLimit 模块在调用前拦截） |

### 4.3 工具页模块 (ToolPage)

| 维度 | 说明 |
|------|------|
| **包含** | 三个独立页面：`/en/`（PDF）、`/en/to-word/`（Word）、`/en/to-html/`（HTML） |
| **页面结构** | H1 + 一句格式专属说明 + 格式切换器 + 编辑器 + 预览 + 转换按钮；随后直接进入全站 Footer |
| **格式切换器** | 视觉上像 Tab（PDF / Word / HTML），实际是 `<a>` 链接导航到对应工具页，当前格式高亮 |
| **文案** | 每个工具页只有独立 H1 和一句说明；不增加 How-to、Why、Features、FAQ、指南推荐或帮助链接行 |
| **共享** | 三个页面共用同一套编辑器布局组件，差异通过 `format`、`lang` props 控制 |
| **边界** | 页面壳只做布局、格式/语言匹配的 SoftwareApplication 注入；编辑和转换逻辑分别由 Editor 和 Converter 模块处理 |

### 4.4 指南模块 (Guide)

| 维度 | 说明 |
|------|------|
| **包含** | 指南列表页 `/en/guides/` + 3 篇指南详情页 |
| **列表页** | 指南卡片网格（标题+摘要+预估阅读时间），Hub 页面角色 |
| **详情页结构** | H1 → 正文（语法说明+代码示例）→ 迷你编辑器（交互试验区）→ 常见错误 → CTA → FAQ → Related Guides |
| **代码示例** | 每个代码块右上角 "Copy" 按钮，一键复制到剪贴板 |
| **迷你编辑器** | 嵌入式 `MiniEditor` 组件，用户可输入 Markdown 并实时看到渲染效果 |
| **CTA** | 文中和文末各一个引导块："Ready to convert? → Convert Markdown to PDF" |
| **内链** | 底部 "Related Guides" 区域链接到其他指南页；CTA 链接到首页/对应工具页 |
| **字数** | 英文版 800-1500 词，中文版可适当简化 |

### 4.5 用户模块 (Auth)

| 维度 | 说明 |
|------|------|
| **输入** | Email+密码 或 Google OAuth Token |
| **输出** | Supabase Session（JWT），用于鉴权和用量追踪 |
| **页面** | `/en/auth/login` — 登录+注册合一页面（noindex） |
| **登录触发点** | 用量超限提示中的 "Sign up for more"；Header 中的 Login 按钮；Dashboard 入口 |
| **边界** | 不涉及付费逻辑（V1.0 无付费功能） |

### 4.6 用量控制模块 (RateLimit)

| 维度 | 说明 |
|------|------|
| **规则** | 匿名用户：**前端提示 2 次/天**（localStorage 软限制，UI 显示）+ **服务端防滥用 10 次/天/IP**（硬限制，绕过 localStorage 仍受限）；登录用户：5 次/天（PDF+Word）；HTML：不限 |
| **追踪方式** | 匿名：localStorage（UX）+ IP rate limit（防滥用）；登录：服务端权威，`consume_quota` RPC 原子扣额（docs/09） |
| **设计说明** | NAT/共享 IP 场景（学校、公司、Cloudflare WARP）下单 IP 可承载多匿名用户，因此服务端硬限不下降到 2/天否则会误伤合法用户。上 captcha/指纹后可考虑收紧 |
| **超限行为** | 弹出提示："You've used your free conversions today. Sign up for 5 free conversions per day." 或登录用户："Today's limit reached. Come back tomorrow." |
| **边界** | 仅负责判断"能否转换"，不负责转换逻辑本身 |
| **失败不扣量** | 转换失败（后端超时/崩溃）不应消耗用户的每日用量 |

### 4.7 历史记录模块 (History)

| 维度 | 说明 |
|------|------|
| **存储** | Supabase DB：user_id, format, filename, file_size, created_at |
| **不存储** | 原始 Markdown 内容和生成的文件（隐私考虑 + 存储成本） |
| **不可重下载** | Dashboard 中明确标注 "Conversion history is for your reference only. Files are not stored on our servers for your privacy."，不显示任何类似"下载"的按钮 |
| **页面** | `/en/dashboard` — 转换历史列表 + 今日剩余用量显示（noindex） |
| **边界** | 仅登录用户可见 |

### 4.8 SEO 基础设施

| 维度 | 说明 |
|------|------|
| **TDK** | 每个页面独立设置 Title / Description / Keywords（参见 SEO 策略附录 C） |
| **JSON-LD** | 工具页：与当前格式、语言和 canonical 一致的 SoftwareApplication；指南页：Article + FAQPage（页面有可见 FAQ 时） |
| **sitemap.ts** | 动态生成，包含所有 index 页面 |
| **robots.ts** | 允许全站抓取，Disallow: /auth/, /dashboard |
| **Open Graph** | 每页独立 og:title, og:description, og:image |
| **Canonical** | 每页设置 canonical URL，避免重复内容 |
| **hreflang** | 英文和中文页面互设，x-default 指向英文 |

### 4.9 i18n 模块

| 维度 | 说明 |
|------|------|
| **语言** | en（默认，SEO 主力）、zh（简化版） |
| **路由** | `/(localized)/[lang]/` 路由分组 |
| **翻译** | 结构化翻译文件，en 为类型源 |
| **中文策略** | UI 文案翻译到位，工具页与英文保持相同的极简结构；指南页可按真实需求调整篇幅 |

### 4.10 公共 UI 模块 (Layout)

| 维度 | 说明 |
|------|------|
| **Header** | Logo（链接首页）+ 导航：Convert to PDF / Word / HTML / Guides + Login/Dashboard |
| **Footer** | 内链区（工具页+指南页链接）+ Legal（Privacy / Terms）+ Language Switcher (EN/中文) |
| **面包屑** | 指南详情页显示：Home > Guides > [当前指南标题] |
| **移动端** | Header 导航折叠为 Hamburger 菜单；编辑器上下排列 |

### 6.2 内链规则（逐条对应 SEO 策略约束 4）

| 链接关系 | 实现方式 | 位置 |
|---------|---------|------|
| **工具页 ↔ 工具页** | 格式切换器（PDF/Word/HTML 三个链接） | 编辑器上方 |
| **工具页 → 指南页** | 全站 Footer 的 Guides 链接 | 工具主体之后 |
| **指南页 → 工具页** | 文中 CTA 横幅 + 文末 CTA 按钮 | 正文中部 + 底部 |

| **guides/ Hub → 指南详情** | 指南卡片列表 | 页面主体 |

### 6.3 格式切换器的关键设计

格式切换器看起来像 Tab 组件，但**实际是导航链接**，确保：
- 每次切换格式 = 导航到新 URL = Google 视为独立页面
- **必须使用 Next.js `<Link>` 实现客户端导航**（不做完整页面刷新），避免白屏/内容闪失
- 编辑器中的内容在切换时**通过 sessionStorage 保持**（用户不丢失已粘贴的内容）
- 当前格式高亮显示，其他格式可点击
- **体验红线：绝对不能出现内容消失再出现的视觉跳动**——切换时应展示骨架屏过渡

## 7. 关键用户流程

### 流程 1：粘贴转换（最高频场景）

```
用户从 ChatGPT/Claude 复制 Markdown 文本
    │
    ▼
打开 markdown-to-pdf.app（首页 /en/）
    │
    ▼
看到编辑器（左侧空白，右侧预览区显示 placeholder 提示）
    │
    ▼
粘贴 Markdown 到编辑器左侧
    │
    ▼
右侧实时预览渲染效果
    │
    ▼
点击 "Convert to PDF" 按钮
    │
    ├──── 未超限 ────► 加载中... → 浏览器自动下载 .pdf 文件 → 完成
    │
    └──── 已超限 ────► 弹出提示 → "Sign up for 5 free conversions/day"
                          │
                          ▼
                     点击注册 → /auth/login → 注册/登录 → 返回首页 → 重新转换
```

### 流程 2：上传转换

```
用户有一个 .md 文件
    │
    ▼
打开首页 → 将 .md 文件拖拽到编辑器区域（或点击上传按钮选择文件）
    │
    ▼
编辑器自动填充文件内容 + 右侧实时预览
    │
    ▼
（可选）用户在编辑器中修改内容
    │
    ▼
选择目标格式（默认 PDF，可通过格式切换器切换到 Word/HTML）
    │
    ▼

## 9. 需要重点设计的页面或流程

### 9.1 工具页编辑器布局（最高优先级）

这是产品的核心体验，需要重点打磨。

**桌面端布局**：

```
┌──────────────────────────────────────────────────────────┐

│  Sub: Convert your Markdown or AI-generated text into    │
│       a professional PDF in seconds.                     │
├──────────────────────────────────────────────────────────┤
│  [PDF] [Word] [HTML]          ← 格式切换器（链接导航）     │
├──────────────────────────────────────────────────────────┤
│                    │                                     │

│   (CodeMirror 6)   │      (Rendered HTML)                │
│                    │                                     │
│   ┌────────────┐   │                                     │
│   │ Drop .md   │   │                                     │
│   │ file here  │   │                                     │
│   └────────────┘   │                                     │
│                    │                                     │
├──────────────────────────────────────────────────────────┤
│  [Upload .md]           [Convert to PDF ▼]    ← 主 CTA   │
│                         剩余 X 次 / 登录获得更多           │
└──────────────────────────────────────────────────────────┘
```

**移动端布局**：

```
┌────────────────────────┐
│ [PDF] [Word] [HTML]    │ ← 格式切换器
├────────────────────────┤
│ [Edit] [Preview]       │ ← Tab 切换编辑/预览
├────────────────────────┤
│                        │
│  Editor or Preview     │
│  (取决于当前 Tab)       │
│                        │
├────────────────────────┤
│  [Upload] [Convert ▼]  │ ← 固定在底部
│  剩余 X 次              │
└────────────────────────┘
```

**重点设计细节**：
- 格式切换器切换时通过 sessionStorage 保持编辑器内容
- 拖拽区域覆盖整个编辑器面板（拖入时全区域变色提示）
- 转换按钮旁显示用量信息（降低超限时的惊讶感）
- 首次访问编辑器为空，只显示明确 placeholder，用户无需先理解或删除示例内容
- 同一浏览器标签页内存在 sessionStorage 内容时恢复内容，支持格式切换和指南 CTA 无缝衔接
- 不使用 `hasVisited` 或 localStorage 区分首次/回访用户
- **桌面端转换按钮始终可见**（fixed 定位在编辑器底部），避免长内容时滚出视窗
- 首屏信息层级：H1 → 一句格式专属说明 → 格式切换器 → 编辑器

### 9.2 超限提示 → 注册转化流程

这是免费转化注册的关键流程。采用**内联提示 + 弹窗双保险**方案：

**方案 A：内联提示（优先触发）**
- 当剩余用量为 0 时，转换按钮文案变为 "Sign up to Convert"，按钮颜色变灰
- 按钮下方内联显示："Sign up for 5 free conversions per day — no credit card needed."
- 用户在投入时间粘贴内容**之前**就能看到限制

**方案 B：弹窗兜底**
- 如果用户仍然点击了灰色按钮，弹出 Modal：

```
┌──────────────────────────────────────┐
│  You've used all free                │
│  conversions for today               │
│                                      │
│  Sign up to get 5 free conversions   │
│  per day — no credit card needed.    │
│                                      │
│  [Continue with Google]  ← 一键注册   │

│  Or come back tomorrow for           │

**核心原则**：让用户在投入时间之前就知道限制，而不是投入时间之后才告知。语气友好，不施压，Google OAuth 降低注册摩擦。

## 10. 页面类型与关键词承接关系说明

### 10.1 工具页（Transactional Intent 承接）

| 承接的搜索意图 | 用户行为预期 | 页面响应方式 |
|--------------|-------------|-------------|
| "md to pdf" "markdown to pdf converter" | 想要一个能用的在线转换工具 | 首屏即编辑器+转换按钮，用完即走 |
| "convert md to word" "md to docx" | 想把 .md 文件转成 Word 格式 | /to-word/ 页面，默认选中 Word 格式 |
| "markdown to html online" | 想把 Markdown 转成 HTML | /to-html/ 页面，强调纯前端隐私安全 |
| "how to convert markdown to pdf" | 想知道步骤但也想用工具 | 当前由可直接操作的工具页自然承接；只有 GSC 证明独立意图且有原创价值时才新增内容页 |

**设计原则**：工具页只负责“做”。用户在 H1 和一句说明后立即输入、预览、转换，不再被附加内容延长任务路径。

### 10.2 指南页（Informational Intent 承接）

| 承接的搜索意图 | 用户行为预期 | 页面响应方式 |

| "markdown new line" "markdown line break" | 想知道 Markdown 怎么换行 | 详尽的语法说明+多个代码示例+交互试验区 |
| "markdown quote" "markdown block quote" | 想知道 Markdown 引用语法 | 单层/嵌套/多段引用语法+示例+常见错误 |
| "markdown cheat sheet" | 想要一页看完所有语法 | 全语法速查表+每项都有交互示例+链接到独立指南 |

**设计原则**：指南页的核心是"教"，然后引导"用"。必须比 markdownguide.org 对应内容更深入（独立页面 vs 大页面的一小节），且有交互式编辑器作为差异化杀手锏。

## 13. 2026-10-04 工具可靠性与统计更新（现行）

- 工具页仍为空白初始态；当前标签页草稿在共享内存中保持，sessionStorage 300ms 防抖保存，导航前立即检查点保存。跨格式与跨语言保持内容。存储失败显示提示，不能可靠恢复的语言/root 导航会被拦截，用户需先复制或下载；刷新时保留浏览器离开提醒。
- 左侧显示源码字符数及 UTF-8 KiB，包含格式符号与空白；右侧显示 sanitize 后正文的不含空白字符数与分词结果。字符按 Unicode 码点计算，固定英文 locale 分词，旧浏览器不支持时不显示词数。仅工具页开启统计，指南正文和迷你编辑器不增加统计。
- 预览最多200KiB UTF-8，保持码点完整；截断后标注“预览片段”。完整输入仍用于全部导出，没有500KiB硬上限。渲染失败保留上次有效预览和统计并显示未更新提示，清空立即归零。
- 点击/拖拽上传共用读取逻辑，大小写无关地接受 .md/.markdown/.txt；支持 UTF-8、BOM UTF-16及检测到的浏览器支持旧编码。显示读取状态及错误，失败保留当前内容，旧读取不能覆盖新选择或手动编辑。
- 下载、打印、复制共用操作锁和状态；空白输入禁用操作。重试重新执行失败快照，内容或格式改变后取消旧重试。复制按钮明确复制 HTML 源码，不提供富文本粘贴。
- 手机操作栏分行，反馈独占一行；小于360px时 HTML 双按钮上下排列。桌面面板不再强制左侧至少460px，平板两面板均可收缩。
- Word 递归保留嵌套/混合列表、后续段落、任务状态、引用内列表/代码/表格和代码换行；有序列表保留文本编号并独立重启。图片仍为替代文字，非br原始HTML不扩展支持。引用表格宽度扣除缩进，表格与单元格使用DXA宽度。
- PDF 仍由浏览器打印保存，不能检测保存/取消，不写历史；Word/HTML下载后最佳努力写历史，历史服务失败不影响导出。

实现与运行边界见 [10-前端化架构补丁](./10-前端化架构补丁.md) 第9节。
