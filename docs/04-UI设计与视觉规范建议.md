## 1. 整体视觉风格说明

### 1.1 风格定位

**Tool-First Modern Minimalism（工具优先的现代极简主义）**

这不是 SaaS 着陆页的华丽风格，也不是开发者文档的纯技术风格，而是介于两者之间的"轻量工具"美学——让用户在 3 秒内理解"该做什么"，30 秒内完成转换。

### 1.2 参考方向

| 参考对象 | 借鉴什么 | 不借鉴什么 |
|---------|---------|-----------|
| **Notion** | 克制与留白、无干扰的工作界面 | 多层嵌套的侧边栏结构 |
| **Linear** | 精致与一致性、过渡动效的克制 | 深色主题为默认的选择 |
| **Vercel** | 黑白灰基调、排版的呼吸感 | 过于开发者导向的术语 |
| **markdowntopdf.com** | — | 全部（过时、粗糙、无移动端适配） |

### 1.3 设计原则

| 原则 | 具体含义 | 反面案例 |
|------|---------|---------|
| **工具感 > 营销感** | 首屏是能用的编辑器，不是 Hero Section + 大图 | 不做 Gradient Hero、不放插图 |
| **静 > 动** | 减少动画、过渡不超过 200ms、无视差滚动 | 不做 Lottie 动画、不做滚动触发效果 |
| **功能 > 装饰** | 工具页只保留完成转换所需的信息和控件 | 不用长文、徽章、卡片或折叠区填充页面 |
| **CodeMirror 不可怕** | 通过文案、留白、浅色底色软化编辑器的"程序员"感 | 不加过多装饰导致信息过载 |
| **信任感优先** | 简洁 = 专业，克制 = 可信 | 不做花哨动画暗示"不靠谱" |

### 1.4 整体氛围关键词

`Clean` · `Functional` · `Approachable` · `Fast` · `Trustworthy`

### 1.5 亮色/暗色模式决策

**V1.0 仅做亮色模式。** 理由：

1. 最大用户群体（非技术用户，占 40-50%）习惯亮色界面
2. 指南页和辅助页在亮色下阅读体验更好
3. CodeMirror 编辑器单独用浅灰底色（`bg-gray-50`），既保持与页面背景的视觉分隔，又不让编辑器看起来太"IDE 风"
4. 暗色模式意味着所有 CSS 需要 `dark:` 变体，V1.0 工作量翻倍不值得

> 暗色模式留给 V2.0，可作为用户偏好功能。

## 2. 页面视觉层级建议

### 2.1 三类页面的层级模型

#### A 类：工具页（首页、/to-word/、/to-html/）— 最高视觉密度

```
[低权重] Header ← 尽量薄，不抢编辑器空间
    │
[中权重] H1 + 一句格式专属说明 ← 说明输入、预览、输出与隐私
    │
[中权重] 格式切换器 [PDF] [Word] [HTML] ← 紧凑、扁平、当前项高亮
    │
[最高权重] 编辑器 + 预览面板 ← 页面绝对核心，占视口 60-70% 高度
    │
[高权重] 操作栏（Upload + Convert + 用量）← 桌面端 sticky
    │
[低权重] Footer
```

**具体建议**：
- H1 字号 `text-2xl`（24px）而非 `text-4xl`，因为核心是编辑器不是标题
- H1 颜色 `text-gray-800` 而非纯黑 `text-black`
- Sub-heading 用 `text-base`（16px）+ `text-gray-500`，一行内完成
- 编辑器最小高度 `min-h-[500px]`（桌面端），确保足够的编辑空间
- 工具栏之后不插入额外内容模块，页面自然收束到 Footer

#### B 类：指南页（/guides/[slug]）— 中等视觉密度，阅读为主

```
[低权重] Header
    │
[低权重] 面包屑 Home > Guides > [标题]
    │
[高权重] H1 ← 指南页 H1 可以大一些（30px），因为这是内容页
    │
[最高权重] 正文内容 ← 阅读体验优先，max-w-3xl
    │
[中权重] 代码示例区 ← 深色底色突出 + Copy 按钮
    │
[中权重] 迷你编辑器 ← 交互式但不抢正文风头
    │
[中权重] CTA 横幅 ← 醒目但不突兀（柔和蓝底色）
    │
[低权重] Related Guides 卡片列表
    │
[低权重] Footer
```

**具体建议**：
- 正文区 `max-w-3xl`（768px），确保英文每行 60-80 字符的舒适阅读长度
- 代码示例用 `bg-gray-900` 深色底 + `text-gray-100` 浅色字——无论页面是亮色，代码块始终深色
- 迷你编辑器高度 200px，用明确的边框容器包裹，标题 "Try it yourself" 用 `text-lg font-medium`
- CTA 横幅用柔和品牌色底色（`bg-blue-50`），不用强对比色

#### C 类：辅助页面（pricing、privacy、terms、login、dashboard）— 低视觉密度

```
[低权重] Header
    │
[中权重] 页面标题
    │
[中权重] 主内容 ← 简单直接
    │
[低权重] Footer
```

**具体建议**：
- 内容区 `max-w-2xl`（672px）居中
- Privacy/Terms 纯文本排版，不需要任何特殊组件
- Login 页面居中卡片式布局，宽度 `max-w-sm`（384px）
- Dashboard 使用左对齐列表，不需要复杂的数据可视化

### 2.2 信息层级的视觉权重分配

| 元素 | 工具页 | 指南页 | 辅助页 |
|------|--------|--------|--------|
| Header | 5% | 5% | 5% |
| H1/标题 | 5% | 15% | 15% |
| 核心内容（编辑器/正文） | 70% | 60% | 70% |
| CTA/操作区 | 15% | 10% | 5% |
| Footer/辅助信息 | 5% | 10% | 5% |

### 2.3 与前述文档的对齐检查

- 产品结构文档 9.1 节已定义的 wireframe 层级结构 → ✅ 完全对齐
- SEO 策略约束 2："工具任务优先，不附加无助于转换的内容" → ✅ 编辑器占 70% 权重，工具后直接进入 Footer
- 交互补充 5.1 节信息层级 → ✅ H1 + Sub-heading + 格式切换器 + 编辑器顺序一致

## 3. 字体与排版建议

### 3.1 字体选择

| 用途 | 推荐字体 | 备选 | 理由 |
|------|---------|------|------|
| **UI 文字**（导航、按钮、标签） | Inter | system-ui stack | 海外用户最熟悉的现代无衬线体，Vercel/Linear 同款 |
| **正文阅读**（指南页、SEO 区） | Inter | 同上 | 统一字体，不引入第二种正文字体 |
| **代码/编辑器** | JetBrains Mono | Fira Code, Source Code Pro | CodeMirror 编辑器和代码块统一使用 |
| **中文** | system-ui fallback | — | 不单独加载中文 Web Font（性能优先），依赖 `-apple-system, "Segoe UI", "Noto Sans SC"` fallback |

**Tailwind CSS 4 配置**：

```
fontFamily: {
  sans: ['Inter', 'system-ui', '-apple-system', 'sans-serif'],
  mono: ['JetBrains Mono', 'Fira Code', 'monospace'],
}
```

**字体加载策略**：
- 仅加载 Inter（400/500/600/700）和 JetBrains Mono（400/700）
- 使用 woff2 格式，总计约 80-120KB
- `font-display: swap` 避免 FOIT（Flash of Invisible Text）
- 通过 Next.js `next/font` 自动优化加载

### 3.2 字号体系

基于 Tailwind CSS 4 默认 scale：

| 层级 | Tailwind Class | 像素 | 使用场景 |
|------|---------------|------|---------|
| Display | `text-3xl` | 30px | 指南页 H1 |
| Heading 1 | `text-2xl` | 24px | 工具页 H1 |
| Heading 2 | `text-xl` | 20px | 指南页 H2、辅助页区块标题 |
| Heading 3 | `text-lg` | 18px | 卡片标题、组件标题 |
| Body | `text-base` | 16px | 正文、按钮文字 |
| Small | `text-sm` | 14px | 辅助信息、placeholder、用量提示 |
| Tiny | `text-xs` | 12px | 标签、时间戳 |

### 3.3 行高与段落间距

| 场景 | 行高 | Tailwind | 段落间距 |
|------|------|---------|---------|
| 正文阅读（指南页、辅助页） | 1.75 | `leading-7` | `space-y-5`（20px） |
| UI 文字（导航、按钮） | 1.5 | `leading-6` | — |
| 编辑器面板标题 | 1.25 | `leading-5` | — |
| 代码块 | 1.5 | `leading-6` | — |

### 3.4 工具页 H1 的特殊处理

工具页 H1 是 SEO 必要元素，但不应喧宾夺主：

```
H1:          text-2xl font-semibold text-gray-800
Sub-heading: text-base font-normal text-gray-500 mt-1
```

- H1 + Sub-heading 总共占 2 行，高度约 80px
- 不用 `font-bold`，用 `font-semibold`（视觉上轻一级）
- 不用 `text-black`，用 `text-gray-800`（柔和一级）

### 3.5 与前述文档的对齐检查

- 主线文档 Lighthouse 90+ 要求 → ✅ 字体控制在 120KB 内，使用 next/font 优化
- SEO 策略 TDK 要求 H1 包含 "Markdown (.md)" → ✅ H1 字号 24px 存在但不抢编辑器风头

## 4. 色彩与按钮风格建议

### 4.1 核心色彩体系

**主色调：蓝灰体系**（专业、可信、不张扬）

| 角色 | 色值 | Tailwind | 使用场景 |
|------|------|---------|---------|
| **Primary** | `#2563EB` | `blue-600` | 主 CTA 按钮、当前选中态、链接默认色 |
| **Primary Hover** | `#1D4ED8` | `blue-700` | 按钮 hover |
| **Primary Light** | `#EFF6FF` | `blue-50` | CTA 横幅背景、轻度高亮 |
| **Background** | `#FFFFFF` | `white` | 页面主背景（工具区） |
| **Surface** | `#F9FAFB` | `gray-50` | 编辑器背景、指南卡片背景 |
| **Border** | `#E5E7EB` | `gray-200` | 分割线、输入框边框、面板边框 |
| **Text Primary** | `#111827` | `gray-900` | 主文字 |
| **Text Secondary** | `#6B7280` | `gray-500` | 辅助文字、placeholder |
| **Text Tertiary** | `#9CA3AF` | `gray-400` | 装饰性图标、CM 行号等非文字元素（见下方修订说明） |

> **修订（2026-08-06，WCAG AA 对比度）**：白底/gray-50 底上 `gray-400` 对比度约 2.8:1，不满足 WCAG AA（4.5:1）。所有承载语义的文本——placeholder、卡片阅读时间、面板副标题、时间戳、空状态说明、页脚版权——统一改用 `gray-500`（`#6B7280`，对比度约 4.8:1）。`gray-400` 仅保留给装饰性图标（chevron、分隔符）与 CodeMirror 行号等非信息性元素。涉及本条目的实现均已按此调整，下文中 `text-gray-400` 用于语义文本的示例（§5.1 阅读时间标签、§5.4 历史列表、§6.4 表单 placeholder、§10.3 面板副文案）以此修订为准。

### 4.2 格式专属色

每种输出格式有专属颜色，用于格式切换器高亮、转换按钮、Dashboard 标签等：

| 格式 | 色值 | Tailwind | 视觉联想 |
|------|------|---------|---------|
| **PDF** | `#DC2626` | `red-600` | Adobe PDF 图标天然红色，用户直觉联想 |
| **Word** | `#2563EB` | `blue-600` | Microsoft Word 蓝色传统 |
| **HTML** | `#F97316` | `orange-500` | HTML5 logo 橙色，Web 技术标识 |

**使用范围**：

| 组件 | PDF 页 | Word 页 | HTML 页 |
|------|--------|---------|---------|
| 格式切换器当前项底线 | `border-red-600` | `border-blue-600` | `border-orange-500` |
| 格式切换器当前项文字 | `text-red-600` | `text-blue-600` | `text-orange-500` |
| 转换按钮背景 | `bg-red-600` | `bg-blue-600` | `bg-orange-500` |
| Dashboard 格式标签底色 | `bg-red-50 text-red-700` | `bg-blue-50 text-blue-700` | `bg-orange-50 text-orange-700` |

**边界**：格式专属色仅用于"与格式直接关联"的元素。页面其他元素（导航、链接、表单、CTA 横幅等）仍使用 Primary Blue。

### 4.3 功能色

| 角色 | 色值 | Tailwind | 使用场景 |
|------|------|---------|---------|
| **Success** | `#16A34A` | `green-600` | 转换成功提示、Copy 成功反馈 |
| **Warning** | `#CA8A04` | `yellow-600` | 用量接近限制时的提示 |
| **Error** | `#DC2626` | `red-600` | 转换失败、表单验证错误 |
| **Info** | `#2563EB` | `blue-600` | 信息提示（与 Primary 同色） |

### 4.4 按钮体系

**四级按钮层级**：

| 层级 | 外观 | 使用场景 | Tailwind 样式 |
|------|------|---------|-------------|
| **Primary** | 实色填充 | Convert to PDF、Sign up | `bg-{format-color} text-white rounded-lg px-6 py-2.5 font-medium shadow-sm` |
| **Secondary** | 边框 | Upload .md、Copy HTML | `border border-gray-300 text-gray-700 rounded-lg px-4 py-2 hover:bg-gray-50` |
| **Tertiary** | 无边框文字链接 | Also download as Word | `text-blue-600 hover:text-blue-700 hover:underline` |
| **Ghost** | 纯文字 | 导航链接 | `text-gray-600 hover:text-gray-900` |

**按钮圆角**：统一 `rounded-lg`（8px），不用 `rounded-full`（过于"SaaS 感"）。

**按钮尺寸**：

| 尺寸 | 高度 | padding | 字号 | 使用场景 |
|------|------|---------|------|---------|
| 大 | `h-11` | `px-8` | `text-base` | Convert 主按钮 |
| 中 | `h-10` | `px-6` | `text-sm` | 默认 |
| 小 | `h-8` | `px-3` | `text-sm` | 标签式操作、Copy 按钮 |

**超限状态按钮**：
- 外观：`bg-gray-200 text-gray-500 cursor-not-allowed`
- 文案变为 "Sign up to Convert"
- 按钮下方内联提示：`text-sm text-gray-500`，内容 "Sign up for 5 free conversions per day — no credit card needed."

### 4.5 编辑器区域色彩

| 元素 | Tailwind | 说明 |
|------|---------|------|
| 编辑器面板背景 | `bg-gray-50` | 略区别于白色页面背景，标识"工作区" |
| 编辑器文字 | `text-gray-900` | 正常深色 |
| 行号 | `text-gray-400` | 调淡，不抢注意力，减少"IDE 感" |
| 预览面板背景 | `bg-white` | 白色，模拟"PDF/文档"最终效果 |
| 面板分隔线 | `border-gray-200` | 编辑器与预览之间 |
| 面板标题区 | `bg-gray-50 border-b border-gray-200 px-4 py-2` | 面板顶部条 |
| 拖拽高亮态 | `border-2 border-dashed border-blue-400 bg-blue-50` | 拖入 .md 文件时的全区域反馈 |

## 5. 卡片、列表、标签、输入框等组件建议

### 5.1 卡片组件

**指南卡片（/guides/ 列表页 + 工具页底部推荐区）**：

```
┌──────────────────────────────────────┐
│  [标题]           text-lg font-medium │
│  [2 行摘要...]    text-sm text-gray-500│
│  4 min read       text-xs text-gray-400│
└──────────────────────────────────────┘
```

样式：`bg-white border border-gray-200 rounded-xl p-6 hover:border-gray-300 hover:shadow-sm transition-all duration-150`

- 列表页网格：桌面端 `grid-cols-3 gap-6`，平板 `grid-cols-2`，移动端 `grid-cols-1`
- 工具页底部推荐区：更紧凑版 `p-4`，摘要只显示 1 行

**CTA 横幅卡片（指南页内嵌）**：

```
┌──────────────────────────────────────────────────┐
│  bg-blue-50 border border-blue-100 rounded-xl p-6 │
│                                                    │
│  Got your formatting right?                        │
│  Download it as a clean PDF →                      │
└──────────────────────────────────────────────────┘
```

- 标题：`text-lg font-medium text-gray-800`
- 链接：`text-blue-600 font-medium hover:underline`
- 不用渐变、不用强对比色、不加图标——让它看起来是内容的一部分而非广告

### 5.2 标签组件

**格式标签（Dashboard 历史记录）**：

```
PDF  → bg-red-50 text-red-700 text-xs font-medium px-2 py-0.5 rounded
Word → bg-blue-50 text-blue-700 text-xs font-medium px-2 py-0.5 rounded
HTML → bg-orange-50 text-orange-700 text-xs font-medium px-2 py-0.5 rounded
```

**阅读时间标签（指南卡片）**：`text-xs text-gray-400`，前方一个 Lucide `Clock` icon（12px）

### 5.3 格式切换器 Tab

```
整体容器：border-b border-gray-200（底部细线贯穿）

未选中：text-gray-500 hover:text-gray-700 py-2 px-4 border-b-2 border-transparent
选中：  text-{format-color} font-medium py-2 px-4 border-b-2 border-{format-color}
```

- 左对齐（不居中），视觉上靠近编辑器
- Tab 文字简短："PDF" / "Word" / "HTML"（前面不加 "to"）
- 高度紧凑：Tab 区域总高度 `h-10`（40px）
- 实现为 Next.js `<Link>` 客户端导航，视觉上像 Tab

### 5.4 列表组件

**Dashboard 转换历史列表**：

```
每行：flex items-center gap-4 py-3 border-b border-gray-100
 ├── 格式 icon（16x16，用格式专属色）
 ├── 文件名 text-sm text-gray-900 font-medium flex-1 truncate
 ├── 格式标签（见 5.2）
 └── 时间 text-xs text-gray-400
```

- 列表上方说明文字：`text-sm text-gray-400`，内容 "Conversion history is for your reference only. Files are not stored on our servers for your privacy."
- 不显示任何类似"下载"的按钮/图标

### 5.5 输入框组件

**Login 页面表单输入**：

```
bg-white border border-gray-300 rounded-lg px-4 py-2.5 text-base w-full
focus:ring-2 focus:ring-blue-500 focus:border-blue-500 outline-none
placeholder:text-gray-400
```

**Google OAuth 按钮**：

```
bg-white border border-gray-300 rounded-lg px-6 py-2.5 font-medium w-full
hover:bg-gray-50 flex items-center justify-center gap-3
左侧 Google G logo（18x18）
```

### 5.6 代码块组件（指南页专用）

```
┌──────────────────────────────────────────────────┐
│  bg-gray-900 rounded-lg overflow-hidden           │
```

## 6. 留白与间距建议

### 6.1 间距体系

所有间距遵循 **8px 倍数原则**（与 Tailwind 默认 4px 单位对齐，所有值为偶数）：

| Token | 值 | Tailwind | 使用场景 |
|-------|-----|---------|---------|
| `xs` | 4px | `p-1` / `gap-1` | 行内元素间距（icon 与文字） |
| `sm` | 8px | `p-2` / `gap-2` | 紧凑间距（标签内边距、列表项小间距） |
| `md` | 16px | `p-4` / `gap-4` | 默认间距（组件内部 padding、表单间距） |
| `lg` | 24px | `p-6` / `gap-6` | 组件之间间距（卡片间距、段落间距） |
| `xl` | 32px | `p-8` / `gap-8` | 区块间距（模块之间） |
| `2xl` | 48px | `p-12` / `gap-12` | 大区块间距（Section 之间） |
| `3xl` | 64px | `p-16` / `gap-16` | 指南页大区块之间 |

### 6.2 工具页关键间距

| 位置 | 间距 | Tailwind | 说明 |
|------|------|---------|------|
| Header 高度 | 56px | `h-14` | 薄而清晰 |
| H1 区上方 | 24px | `pt-6` | Header 与标题间 |
| H1 区下方 | 16px | `mb-4` | 标题与格式切换器间 |
| 格式切换器下方 | 16px | `mb-4` | 切换器与编辑器间 |
| 编辑器高度 | ≥500px | `min-h-[500px]` | 桌面端充足空间 |
| 编辑器内部 | 16px | `p-4` | 内容与边框间 |
| 操作栏 | 12px/16px | `py-3 px-4` | 内部间距 |
| 工具栏 → Footer | 现有布局自然间距 | 不新增 Section padding | 页面直接收束，不制造“还有内容必须读”的负担 |

### 6.3 指南页关键间距

| 位置 | 间距 | Tailwind |
|------|------|---------|
| 面包屑下方 | 16px | `mb-4` |
| H1 下方 | 32px | `mb-8` |
| 正文段落间 | 20px | `space-y-5` |
| 代码块上下 | 24px | `my-6` |
| 迷你编辑器上下 | 32px | `my-8` |
| CTA 横幅上下 | 40px | `my-10` |
| Related Guides 上方 | 64px | `mt-16` |

### 6.4 内容区最大宽度

| 页面类型 | 最大宽度 | Tailwind | 说明 |
|---------|---------|---------|------|
| 工具页编辑器 | 1280px | `max-w-6xl` | 编辑器需要宽度 |
| 指南页正文 | 768px | `max-w-3xl` | 阅读舒适度 |
| 辅助页面（privacy、terms） | 672px | `max-w-2xl` | 简单内容 |
| Login 页面 | 384px | `max-w-sm` | 表单卡片 |
| Header 内容 | 1280px | `max-w-6xl` | 与编辑器对齐 |

### 6.5 留白的核心原则

**编辑器周围留白更多**——信息密度高的区域需要更多呼吸空间：
- 编辑器外围 padding ≥ 24px
- 格式切换器与编辑器之间 16px
- 操作栏按钮之间 ≥ 16px

**工具完成后及时收束**——不添加额外背景带、推荐卡片或人为留白来延长页面。

## 7. 界面一致性建议

### 7.1 全局一致性规则

| 维度 | 规则 | 说明 |
|------|------|------|
| **Header** | 所有页面完全相同的 Header 组件 | 高度、布局、链接不变 |
| **Footer** | 所有页面完全相同的 Footer 组件 | 同上 |
| **圆角** | 统一 `rounded-lg`（8px） | 按钮、卡片、输入框、代码块、编辑器容器均一致。仅头像用 `rounded-full`，弹窗用 `rounded-2xl` |
| **阴影** | 仅弹窗用 `shadow-xl`，卡片 hover 用 `shadow-sm` | 其他元素不使用阴影 |
| **过渡** | 统一 `transition-all duration-150` | 150ms，所有 hover/状态变化 |
| **Icon** | 统一使用 Lucide React 线性风格 | 不混用实心 icon，不混用其他 icon 库 |
| **格式色** | PDF=红、Word=蓝、HTML=橙 | 在格式切换器、按钮、标签、Dashboard 中保持一致 |
| **链接** | `text-blue-600 hover:text-blue-700 hover:underline` | 全站链接统一样式 |

### 7.2 编辑器一致性（主编辑器 vs 迷你编辑器）

| 维度 | 主编辑器（工具页） | 迷你编辑器（指南页） |
|------|-------------------|---------------------|
| 容器 | `border border-gray-200 rounded-lg` | `border border-gray-200 rounded-lg` |
| 面板标题样式 | `text-sm font-medium text-gray-500 px-4 py-2 border-b bg-gray-50` | 同左 |
| 面板标题文案 | "Markdown Input" / "Live Preview" | "Markdown Input" / "Preview" |
| 面板标题副文案 | 左侧小字 "Paste from ChatGPT, Claude, or any text editor" | 无 |
| 编辑器字体 | JetBrains Mono 14px | JetBrains Mono 13px（略小） |
| 高度 | ≥500px（桌面）/ ≥300px（移动） | 200px |
| 行号 | 显示 | 不显示（节省空间） |
| 操作栏 | Upload + Convert + 用量 | 仅底部一行 CTA 链接 |
| 语法高亮 | 完整 | 完整（保持一致） |

### 7.3 工具页主体一致性

三个工具页使用同一结构，只替换格式、语言和转换动作：

```
<ToolPage>
  <H1 />
  <OneSentenceSubheading />
  <FormatSwitcher />
  <EditorAndPreview />
  <EditorToolbar />
</ToolPage>
<Footer />
```

- H1 与一句说明之后立即进入操作，不增加 Hero、信任徽章、步骤条或帮助链接行。
- 工具栏之后直接进入 Footer，不渲染 How-to、Why、Features、FAQ 或指南推荐。
- PDF、Word、HTML 通过现有格式专属色区分，不改变整体灰白视觉体系。
- FAQ 手风琴和 Related Guides 仍可用于确有可见内容需求的指南页，不属于工具页组件。

## 8. 需要重点优化的页面

### 8.1 首页 `/en/`（最高优先级）

**核心挑战**：CodeMirror 编辑器对非技术用户看起来"很程序员"。

**优化策略**：

| # | 策略 | 具体做法 |
|---|------|---------|
| 1 | 软化编辑器外观 | 用 `bg-gray-50` 浅灰底色（不是深色主题），行号颜色调到 `text-gray-300` |
| 2 | 面板标题加副文案 | 左侧 "Markdown Input" 下方小字 "Paste from ChatGPT, Claude, or any text editor"，用 `text-xs text-gray-400` |
| 3 | 首次访问保持空白 | 不预填示例，仅保留明确 placeholder；sessionStorage 有内容时恢复 |
| 4 | 转换按钮视觉突出 | Convert 按钮用大号（`h-11`）+ 格式专属色实色填充，是页面仅次于编辑器的第二视觉焦点 |
| 5 | 工具后直接收束 | 操作栏之后不增加背景带、卡片、FAQ 或推荐模块，直接进入 Footer |
| 6 | 桌面端按钮始终可见 | 操作栏使用 sticky 定位，长内容时不滚出视窗 |

### 8.2 移动端工具页（高风险）

**核心挑战**：格式切换器 + 编辑/预览 Tab + 编辑器 + 底部操作栏，层叠控件太多。

**优化策略**：

| # | 策略 | 具体做法 |
|---|------|---------|
| 1 | 格式切换器紧凑化 | 三个 Tab 均分宽度，高度 `h-10`，不加图标只留文字 |
| 2 | 双层 Tab 紧贴 | 格式切换器 + 编辑/预览 Tab 之间 `gap-0`（无间距），形成"控制面板"整体 |
| 3 | 编辑器充足 | 最小高度 `min-h-[280px]`，确保粘贴后有可视区域 |
| 4 | 底部固定操作栏 | `fixed bottom-0 left-0 right-0 bg-white border-t shadow-sm py-2 px-4 z-50` |
| 5 | Convert 按钮占主导 | 按钮占 65% 宽度，Upload 缩为图标按钮（上传箭头 icon） |
| 6 | 不遮挡编辑器 | 操作栏高度 `h-14`（56px），编辑器底部预留等高 `pb-14` |

### 8.3 指南页 `/en/guides/markdown-new-line` 等（SEO 流量首页之一）

**核心挑战**：教育内容 + 交互编辑器 + CTA 三种元素共存，容易混乱。

**优化策略**：

| # | 策略 | 具体做法 |
|---|------|---------|
| 1 | 正文为绝对主角 | 正文区 `max-w-3xl` 居中，两侧大量留白 |
| 2 | 迷你编辑器明确包裹 | 用 `border rounded-xl overflow-hidden` 容器，标题 "Try it yourself" 在容器上方 |
| 3 | CTA 不像广告 | 用 `bg-blue-50 border border-blue-100 rounded-xl p-6`，文案自然过渡 |
| 4 | 代码与渲染并排 | Markdown 源码（左）和渲染效果（右）用 `grid grid-cols-2`（桌面端），直观展示"写→变" |

### 8.4 格式切换器（贯穿所有工具页）

**核心挑战**：需要被注意到但不能太突出。

**设计方案**：

```
桌面端：
┌─────────────────────────────────────────────────┐
│  PDF        Word        HTML                     │
│  ___                                             │
│  红色2px底线  灰色文字    灰色文字                  │
└─────────────────────────────────────────────────┘

移动端：
┌──────────────────────────┐
│   PDF  │  Word  │  HTML  │
│   ___  │        │        │
└──────────────────────────┘
```

- 桌面端左对齐，移动端均分宽度
- 选中态：格式专属色 2px 底线 + 文字变色 + `font-medium`
- 未选中态：`text-gray-500`，hover 时 `text-gray-700`
- 整体容器底部有 `border-b border-gray-200` 贯穿细线

## 9. 不建议采用的设计方向

### 9.1 明确的反模式清单

| 不要做 | 原因 | 正确方向 |
|--------|------|---------|
| **Hero Section / 大图首屏** | 核心是"打开即用"，Hero 让用户多滚一屏才能开始操作 | 首屏即编辑器 |
| **渐变色背景** | 暗示"营销页/着陆页"，与工具站定位不符 | 纯色背景（白/灰） |
| **Glassmorphism / 毛玻璃** | 增加视觉噪音，与极简主义冲突，且增加 GPU 负担 | 纯色容器 + 清晰边框 |
| **动画密集的 Loading** | 用户等转换时要的是"快"的感觉，不是好看的动画 | 简单 Spinner + 文字进度提示 |
| **深色主题编辑器** | 最大用户群是非技术用户，深色加剧"程序员工具"感 | 浅灰底色编辑器 |
| **Sidebar 布局** | 12 页没有需要侧边导航的内容深度 | 顶部导航 + 内容居中 |
| **Emoji 密集的 UI** | 海外工具站的专业感优先，emoji 降低可信度 | 使用 Lucide icon 替代 |
| **过多色彩变体** | 格式专属色（红蓝橙）+ 功能色已有 6-7 种，再多就乱 | 严格控制在已定义色彩体系内 |
| **Sticky header 阴影** | 视觉噪音，Header 不需要滚动时加阴影 | 固定高度 Header + `border-b border-gray-200` |
| **工具页堆叠 SEO/营销模块** | 为字数增加 How-to、Features、FAQ、徽章或推荐卡片 | 工具栏后直接进入 Footer；信息需求由真正的指南页承接 |
| **Toast/Notification 堆叠** | 转换成功就一个反馈，不需要多通道提示 | 单一反馈通道（操作栏内联显示结果） |
| **移动端强制引导弹窗** | "Subscribe" 弹窗被 Google 惩罚（intrusive interstitials） | 零弹窗（除超限场景外） |
| **rounded-full 按钮** | 完全圆角按钮过于"SaaS 感"，与工具站定位不符 | 统一 `rounded-lg`（8px） |

### 9.2 工具页内容负担的视觉红线

| 不要做 | 为什么 | 当前规则 |
|--------|--------|---------|
| 工具后追加长文 | 用户已经完成或准备完成任务，继续阅读不是必要步骤 | 操作栏后直接进入 Footer |
| 折叠 FAQ/帮助模块 | 即使默认收起，也增加选择和理解成本 | FAQ 留在有可见正文支撑的指南页 |
| 信任徽章/步骤条 | 单一工具不需要再次解释“如何开始” | 一句说明 + placeholder 足够 |
| 为 SEO 新建薄内容页 | 增加索引、内链和维护成本，且可能分散现有页面主题 | 必须先有 GSC 证据与原创价值 |

**判断标准**：任何新增元素都要证明能缩短“输入 → 预览 → 转换”路径，或解决已被真实数据确认的问题；否则不进入工具页。
