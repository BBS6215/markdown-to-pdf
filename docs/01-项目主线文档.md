## 1. 项目名称

**Markdown to PDF** (域名: markdown-to-pdf.app)

## 2. 项目背景

随着 AI 工具（ChatGPT、Claude、Gemini 等）的普及，大量用户日常获得的 AI 生成内容都是 Markdown 格式。这些用户需要将 Markdown 转换为 PDF、Word、HTML 等通用格式，用于分享、提交、打印或归档。

基于 Ahrefs/Semrush/Google Trends 的详细 SEO 调研（数据截至 2026-03-17）：
- **md to pdf**: 月搜索量 6,600，KD 69（高竞争但流量最大）
- **markdown to pdf**: 月搜索量 6,600，KD 61
- **md to word**: 月搜索量 2,400，KD 12（最低竞争，突破口）
- **md to html**: 月搜索量 1,900，KD 27
- 低 KD 内容词：markdown new line (KD 22)、markdown quote (KD 22) 等

市场现有竞品（markdowntopdf.com DR 31、markdowntoword.net DR 28）体量不大，存在以垂直精确匹配域名（EMD）切入的机会。

## 3. 项目目标

打造一个面向海外用户的专业 Markdown 格式转换在线工具站，通过以下路径实现被动收入：
1. 提供高质量的 MD→PDF/Word/HTML 转换功能
2. 通过低 KD 关键词（语法指南 + to-word）获取早期 SEO 自然流量
3. 逐步积累网站权重，最终在高流量主词（md to pdf）上获得排名
4. 后续通过广告、Freemium、API 售卖等方式变现

## 4. 目标用户

| 用户群体 | 核心需求 | 场景 |
|---------|---------|------|
| **AI 工具使用者**（最大群体） | AI 生成的 Markdown 内容转为 PDF/Word 分享或提交 | ChatGPT/Claude 输出→复制粘贴→转换下载 |
| 程序员/开发者 | README、技术文档转 PDF/HTML | 项目文档导出 |
| 技术写手/产品经理 | 需求文档、报告转 Word/PDF | 协作和汇报 |
| 学生/研究人员 | 笔记、论文草稿转 PDF | 提交作业、归档 |

**核心洞察**：目标用户的最大来源不再是"会写 Markdown 的程序员"，而是"被 AI 工具塞了一堆 Markdown 的普通人"。这意味着界面必须对非技术用户极其友好——**首页即入口，粘贴即转换**。

## 5. 核心使用场景

1. **粘贴转换**（最高频）：用户从 AI 工具复制 Markdown 文本 → 粘贴到首页编辑器 → 预览 → 一键转为 PDF/Word/HTML 下载
2. **上传转换**：用户有 .md 文件 → 拖拽/上传到首页 → 选择目标格式 → 下载
3. **在线编辑**：用户在编辑器中直接写/修改 Markdown → 实时预览 → 导出
4. **语法查阅**：用户搜索"markdown new line"等语法问题 → 进入指南页学习 → 顺便使用转换工具

## 6. 本版本范围（V1.0 完整版）

> 不分 MVP 阶段，所有功能一次性开发完成后部署上线。

### 6.1 核心转换功能
- [x] **MD → PDF**：首页核心功能，浏览器原生打印保存，基础排版（GitHub风格），无法检测保存或取消
- [x] **MD → Word**：SEO 突破口（KD 12），浏览器docx包生成，递归保留嵌套列表、任务与引用内内容
- [x] **MD → HTML**：纯前端转换，零成本，完全免费无限制，数据不离开浏览器

### 6.2 编辑器与交互
- [x] **首页即入口**：打开网站直接看到编辑器，粘贴即用
- [x] **在线 Markdown 编辑器**：语法高亮（CodeMirror 6）
- [x] **实时预览**：编辑器右侧实时渲染 Markdown
- [x] **拖拽上传**：支持拖拽或点击上传 .md 文件
- [x] **一键转换 + 下载**：转换后直接触发浏览器下载

### 6.3 用户系统
- [x] **注册/登录**：Supabase Auth（Email + Google OAuth）
- [x] **免费转换**：三种格式均无需登录、无每日配额，长文仅限制自动预览，导出仍为全文
- [x] **转换历史**：登录用户可查看历史转换记录（Dashboard）

### 6.4 SEO 基础设施
- [x] **工具页结构**：H1 + 一句格式专属说明 + 转换工具；工具之后直接进入全站 Footer，不堆叠营销或 SEO 内容
- [x] **语法指南页**：3 篇指南（markdown-new-line, markdown-quote, markdown-cheat-sheet）
- [x] **指南页差异化**：嵌入交互式迷你编辑器 + 代码一键复制 + 内容 800-1500 词（英文）
- [x] **结构化数据**：工具页仅输出与当前格式、语言、URL 一致的 SoftwareApplication；FAQPage 仅用于同页存在可见 FAQ 的指南页
- [x] **sitemap.ts + robots.ts**
- [x] **Open Graph + Twitter Card**
- [x] **TDK 策略**：Title 必须包含 "Markdown (.md)"，避免 MD 歧义
- [x] **Canonical + hreflang**：每页设置 canonical URL，中英文互设 hreflang
- [x] **内容减负原则**：工具页不以字数、FAQ 数量或关键词堆叠作为质量指标；用户可直接输入并转换
- [x] **新增页面门槛**：只有 Google Search Console 等真实搜索数据证明存在独立需求，且能提供区别于现有页面的原创用户价值时，才新建 SEO/承接页

### 6.5 多语言
- [x] **中文 + 英文**（英文为默认/SEO 主力语言）
- [x] i18n 架构预留扩展到更多语言

## 10. 风险与待确认问题

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| Render 内存不足 | Puppeteer 崩溃 | 从 $7 测通→上线前升 2GB；Browser 实例池化复用 |
| Word 生成质量差 | docx 包对复杂格式支持有限 | 先用 docx 包，不够再切 Pandoc（Docker 加安装） |
| "MD" SEO 歧义 | Google 误判为 Maryland/Medical Doctor | TDK 全部写 "Markdown (.md)"，正文高频出现 markdown 全称 |
| 域名 .app 信任度 | 略低于 .com | .app 强制 HTTPS 是优势，且 Google 不歧视 .app |
| 竞品反应 | markdowntopdf.com 可能优化 | 差异化在于首页即入口、AI 用户友好、多格式支持 |

**已确认问题：**
1. 域名 markdown-to-pdf.app → 已上线
2. Supabase 项目 → **新建独立项目**，与 Glintlint 完全隔离
3. PDF 排版质量 → **基础排版**（干净整洁、代码块高亮、表格正常、分页合理，类似 GitHub Markdown 渲染风格）
4. 免费转换 → **三种格式均无每日配额**；登录仅用于查看Word/HTML导出历史，PDF不写历史
